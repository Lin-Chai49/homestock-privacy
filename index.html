二“不收集”是什么意思

这里的“不收集”是指开发者收不到。应用没有账号，没有登录，也没有把数据库上传到服务器。你在屏幕上输入的内容仍然会留在这台手机的 HomeStockDB 里。

关于页上的那句话

设置页底部和“我的”页写着本地存储。设置里的原文是“所有数据本地存储，零数据采集，无网络请求”。“我的”页的角标写着“本地存储 · 零隐私顾虑”。这两句指的是开发者收不到、应用代码不去请求网络。它不表示手机上没有一份本地数据库。

五物品、消耗和购物清单

入库屏幕让你填写：名称、类别、品牌、规格、数量、单位、最低库存、购买日期、到期日期、购买金额、备注、存放位置。购买金额只用于本机上的花费图表，不是支付。单位是固定选项，例如盒、瓶、袋、枚、件、颗、罐、杯、支、提、克、毫升、包。默认最低库存是 1。

入库页还有四个填表示例：乳制品、蔬果、烘焙、药品。点一下会填上类别、存放位置、单位和到期日，仍然只写进本机。

每条物品记录里还有 barcode 和 imageUrl 两个空字段。这一版的入库屏幕不填写它们。应用不打开相机，不打开相册，也不扫码。不要把这两个字段理解成已经在读你的照片。

消耗一条记录时，应用记下物品名称、数量、你选的场景和可选备注，以及当时的时间。场景是七个固定标签：早餐、上午、午餐、下午、晚餐、睡前、日常。不是传感器。

购物清单里的“建议去处”是写死在应用里的类别标签，不是在查询这些商店，也没有打开它们的网站。

这些开关不发通知

版本 1.0.0 不发送系统通知。没有定时任务去读这七个开关，首页也不读它们。应用不声明 POST_NOTIFICATIONS。免打扰时段因此也不会生效。开关留在数据库里，只是设置值。

入库页在已选存放位置时会显示一句“将于过期前 N 天自动通知”。N 是上面的临期阈值，默认 3。这句话只是屏幕上的提示。没有任何任务按这个天数去发送通知。

七本机计算

临期分档、用近 30 天消耗估计还能用几天、是否放入购物清单、花费和浪费图表，都在这台手机上算。应用代码里没有 fetch、XHR、WebSocket 或上报接口。图表库不会为了这些图去下载地图或统计脚本。

到期日按本地日历的 0 点计算还剩几天，然后分成五档。分档用的是固定界限，不读设置里的临期阈值：

还剩画面上的字
已经过了到期日已过期
0 到 2 天紧急
3 到 7 天临期
8 到 30 天关注
超过 30 天，或没有有效日期新鲜

估计“还能用几天”时，应用把最近 30 天消耗数量的绝对值加总，再除以 30，得到日均消耗。当前数量除以这个日均，就是预计天数。这 30 天里没有消耗时，预计天数不作有限数字，单凭这一条不会触发自动补货。

自动补货不是后台任务。购物清单页有一个“同步自动补货”按钮，点下去才跑。对状态为 active 的物品，当前数量小于或等于该物品的最低库存，或者预计天数是有限数字并且小于 7，就会在购物清单里补一条。来源记为 auto，建议去处用上面那张表，估计价格用这件物品的金额。同名且未买完的条目不会重复添加。应用不联系那些商店。

八导出、导入、演示数据和清空

这些按钮都在“设置 → 数据管理”。

操作实际做什么
导出数据（JSON）在内存里拼一份 JSON，包含 schema（值为 HomeStockDB）、version（1）、exportedAt，以及六个存储的全部行，含昵称和家庭住址。然后开始下载，文件名形如 homestock-backup-YYYY-MM-DD-HHmm.json。应用不上传这个文件。你若把它存进“下载”或其他应用，那份副本不受本应用卸载的影响。
导入备份你从系统文件选择器选一个 JSON。先有一次确认：“导入将覆盖所有现有数据”。schema 不是 HomeStockDB 就停止，并提示备份文件格式不正确。通过后，应用先清空六个存储，再写入文件。这会覆盖物品，也会覆盖类别、位置和设置，包括昵称与住址。
加载演示数据确认框写的是向当前数据库追加约 20 件示例物品和消耗记录。代码在现有数据后面追加示例物品、对应的消耗记录和几条购物清单，不先调用清空。确认框里的“追加”和代码一致。
清空全部数据按钮上的短句写着删除物品、消耗、购物记录，并保留类别与位置。连续确认两次后，删除物品、消耗记录和购物清单。保留类别、位置和设置。昵称、家庭角色、家庭人数和家庭住址还在。第二次确认写明该操作无法撤销。

导出的 JSON 在 1.0.0 里不加密。谁能打开那个文件，谁就能读到物资清单和你填过的住址。

九权限和系统备份

清单只声明一项权限：android.permission.INTERNET。Capacitor 用 https 方案把随包的页面交给 WebView（androidScheme 为 https），这项权限是为了那次本机加载。应用同时声明 usesCleartextTraffic="false"，并且不允许混合内容。运行时没有明文请求，也没有应用自己发出的网络请求。

清单不声明相机、麦克风、定位、电话、短信、通讯录、外部存储读写、通知或生物识别。应用代码不读剪贴板。

android:allowBackup="false"，android:fullBackupContent="false"。自定义 dataExtractionRules 把 root、database、file、sharedpref、external 从云备份和换机传输里都排除。系统的自动云备份不会带走 HomeStockDB。

工程里有一个不导出的 FileProvider，authority 是 com.chailin.homestock.fileprovider。路径文件里有 external-path 和 cache-path，两条的 path 都写成一个点，也就是不收窄到某个子目录。这一版的屏幕不用它把文件交给别的应用。导出走的是上面的 JSON 下载。清单也没有声明外部存储权限。

卸载应用会清掉这个应用的 WebView 存储，包括 HomeStockDB。已经下载到别处的 JSON 不会跟着消失。

十随包带上的库

下面这些库在构建时打进安装包，应用没有给它们配账号或统计地址：Vue 3、Vue Router、Pinia、idb、ECharts、dayjs、Capacitor 6。没有广告 SDK、统计 SDK、推送 SDK、崩溃收集或社交分享 SDK。本政策页同样不引入这些库。

十一儿童

悦家库存是给建立这份家庭账的人用的物资工具，不是儿童服务，也没有账号。开发者收不到手机里记下的昵称、住址或药品名称。本政策不把应用说成面向儿童，也不宣称某个年龄分级。

十二安全边界

本地数据的安全取决于这台手机的锁屏和系统加密。版本 1.0.0 没有加密备份，没有单独的隐私弹窗。要看这份说明，打开本页。设置里的“关于”列出版本、著作权人和“零数据采集”那句话，没有政策日志。

十三政策变更

如果以后的版本开始发送通知、读取照片，或把数据传到开发者的服务器，会先改本页，并改页首的日期。版本 1.0.0 不会在启动时弹出确认。关于页也没有政策日志。

HomeStock privacy policy

HomeStock (悦家库存) version 1.0.0, package com.chailin.homestock, versionCode 2. Developer: 柴琳. This page applies from 2026-05-13 and was rewritten on 2026-11-01 to match that build. The minimum system is Android 7.0 (minSdk 24). targetSdk is 35. 中文

“Not collected” means the developer does not receive it. The app has no account and no login. What you type stays in the on-device database HomeStockDB unless you export a file. A record rests in three places only: the characters you type, then HomeStockDB on this phone, then a JSON file if you export one. The developer cannot read the database. The file is not encrypted, and the app does not upload it.

The About block says “所有数据本地存储，零数据采集，无网络请求.” The More screen adds a badge, “本地存储 · 零隐私顾虑.” Both mean the developer receives nothing and the app code makes no network request. They do not mean the phone has no local database.

Database

On first launch the app creates IndexedDB HomeStockDB, version 1, and writes the preset categories, preset places, and one default settings row. Only this app’s WebView origin can read it. The six stores are items, categories, locations, consumptions, shoppingList, and settings. A new item starts with status active. Opening the home screen writes expired onto an active item whose expiry date has passed. Recording the quantity down to 0 writes consumed.

The entry form stores a name, category, brand, specification, quantity, unit, minimum stock, purchase date, expiry date, price, note, and a storage place. Price is used only for charts on the device. It is not a payment. Units are a fixed list, including 盒、瓶、袋、克、毫升. Default minimum stock is 1. Four fill-in examples (dairy, produce, bakery, medicine) write a category, place, unit, and expiry onto the form. That still stays on the device.

Each item row also has empty barcode and imageUrl fields. This version’s form does not fill them. The app does not open the camera, does not open the photo library, and does not scan a code.

Eight categories ship with the app: 食品, 药品, 日用品, 清洁用品, 调味品, 罐头, 茶饮, and 其他. This version’s screens do not add or delete a category. Import can replace the table. If you file something under medicine, the name and expiry stay on the device. The developer does not receive them and the app does not diagnose anything.

Twelve places ship with the app. They are room labels, not GPS. The preset description for the fridge says “冰箱主仓 · 0-4°C”, and the freezer says “冰箱冷冻层 · -18°C”. Those are stored sentences, not a thermometer. The names are 冰箱·冷藏, 冰箱·冷冻, 厨房·调料柜, 厨房·常温柜, 厨房·米柜, 厨房·茶柜, 药箱, 卫生间·储物柜, 卫生间·清洁柜, 卧室·衣柜, 客厅·储物柜, and 玄关·鞋柜. This version’s screens do not add or delete a place. Import can replace the table.

A consumption row stores the item name, amount, a scene you pick, an optional note, and the time. The seven scenes are 早餐, 上午, 午餐, 下午, 晚餐, 睡前, and 日常. They are labels, not sensors.

A shopping row can store a suggested place name. Those names are fixed labels: 食品, 调味品, and 罐头 map to 盒马生鲜; 日用品 and 清洁用品 map to 京东超市; 药品 maps to 京东大药房; 茶饮 and 其他 map to 永辉超市. The app does not contact those stores.

What settings store

The first-run screen requires a nickname of 2 to 20 characters. The home screen and the More screen show it. The More screen also shows the role and the household size. Settings can store a household role (家庭主管, 家庭主妇/主夫, 双职工, 独居, or 多代同堂; default 家庭主管), a household size (default 3, range 1 to 20), and an optional address of up to 50 characters. The address is text you type. The app does not declare a location permission and does not read GPS.

Theme is one of 家居暖色, 深色模式, or 清新自然, default 家居暖色. It only changes colors on the device. List layout is 货架式, 列表式, or 紧凑式, default 货架式. Sort is expiry ascending, expiry descending, name, quantity high to low, or recently updated, default expiry ascending. The expiry threshold defaults to 3 and can be set from 1 to 30. The minimum-stock ratio defaults to 0.2 and can be set from 0.05 to 0.5. Auto-buy does not read that ratio. It reads each item’s own minimum stock. All of this sits in the settings row under the key app. onboardedAt is the on-device time when setup finished. Font size defaults to md and the date format defaults to YYYY-MM-DD. This version’s settings screen does not edit those two.

Reminder switches

Settings shows seven switches: 临期提醒, 已过期提醒, 库存不足提醒, 购物清单更新, 每周报告（周一上午）, 月度总结（每月初）, and 免打扰时段（22:00-07:00）. Saving writes them into settings.notifications. The weekly report defaults to off. The other six default to on. The quiet-hours clock is stored as 22:00 to 07:00, and the settings screen does not edit those two times.

Version 1.0.0 does not post a system notification. No scheduled job reads the switches, and the home screen does not read them either. The app does not declare POST_NOTIFICATIONS. Nothing applies the quiet hours, because there is no reminder job. The add-item screen shows the sentence “将于过期前 N 天自动通知”, where N is the stored threshold, default 3. That sentence is a hint on the form. No job sends a notification from it.

On-device calculations

Expiry bands, a days-to-empty estimate from the last 30 days of consumption, the shopping suggestion, and the spend and waste charts are computed on the phone. The app source does not call fetch, XHR, WebSocket, or a beacon.

Days until expiry use local midnight. The bands are fixed and do not read the settings threshold: before the expiry date is 已过期; 0 to 2 days is 紧急; 3 to 7 is 临期; 8 to 30 is 关注; more than 30, or a date that does not parse, is 新鲜.

Days to empty divides the current quantity by the average daily use. Average daily use is the absolute amount consumed in the last 30 days, divided by 30. If that window has no consumption, the estimate is not a finite number, and this rule alone does not add a shopping row.

Auto-buy runs only when you press 同步自动补货 on the shopping screen. It is not a background job. For an active item, a row is added when the quantity is less than or equal to that item’s minimum stock, or when the days-to-empty number is finite and below 7. The row’s source is auto, the suggested place comes from the label table, and the estimated price is the item’s price. An unfinished row with the same name is not duplicated.

Export, import, demo data, and clear

All four actions are under Settings, then 数据管理.

  • Export JSON. The app builds one document in memory. It includes schema (HomeStockDB), version, exportedAt, and every row of the six stores, including the nickname and address. It then starts a download named like homestock-backup-YYYY-MM-DD-HHmm.json. The app does not upload that file. A copy you keep in Downloads stays after you uninstall the app. The file is not encrypted.
  • Import. One confirmation comes first. You pick a JSON file. If schema is not HomeStockDB, import stops and the app says the backup format is wrong. If it matches, the app clears all six stores and writes the file. That replaces items, categories, locations, and settings, including the nickname and address.
  • Demo data. The confirmation says it will append about 20 sample items and consumption rows. The app appends sample items, their consumption rows, and a few shopping rows. It does not delete your existing items first.
  • Clear all. The button’s short line says items, consumption, and the shopping list are removed, and that categories and places stay. After two confirmations, the app deletes items, consumption rows, and the shopping list. It keeps categories, locations, and settings. The nickname, role, household size, and address remain. The second confirmation says the action cannot be undone.

Permission and backup

The manifest declares one permission, android.permission.INTERNET. Capacitor loads the bundled page in the WebView on an https scheme (androidScheme is https), and that permission is what allows the local load. usesCleartextTraffic is false, and mixed content is off. The manifest does not declare the camera, microphone, location, phone, SMS, contacts, external storage, notifications, or biometrics. The app code does not read the clipboard.

android:allowBackup is false and android:fullBackupContent is false. dataExtractionRules exclude root, database, file, sharedpref, and external from both cloud backup and device transfer. Automatic cloud backup does not take HomeStockDB.

The project includes a FileProvider, authority com.chailin.homestock.fileprovider, and it is not exported. Its path file lists external-path and cache-path, and both paths are a single dot, so they are not limited to a subdirectory. The screens in this version do not use it to hand a file to another app. Export is the JSON download above. The manifest does not declare an external-storage permission.

Uninstall removes the app’s WebView storage, including HomeStockDB. It does not remove a JSON file you already saved somewhere else.

Libraries, children, and the limit of this text

Vue 3, Vue Router, Pinia, idb, ECharts, dayjs, and Capacitor 6 are bundled in the install. The app does not point them at an account or an analytics endpoint. There is no ad, analytics, push, crash, or social SDK. This page does not load those libraries either.

HomeStock is a household inventory tool for the person who sets it up. It is not a children’s service and it has no account. The developer does not receive the nickname, address, or medicine names stored on the phone. This policy does not assign an age rating.

Safety of the on-device data is the phone’s lock screen and encryption. Version 1.0.0 has no encrypted backup and no privacy popup at launch. This page is the notice. About shows the version, the developer, and the local-storage sentence. It has no policy log. If a later version starts posting notifications, reading photos, or sending data to the developer, this page and the date at the top will change first. The 2026-05-13 text described reminders and an encrypted backup the app does not have. Those sentences are gone.
